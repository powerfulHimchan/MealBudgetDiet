# MealBudgetDiet 요구사항 명세서

- 문서 버전: 1.2
- 작성일: 2026-09-08
- 최종 변경일: 2026-09-09
- 상태: 요구사항 확정
- 대상 플랫폼: 모바일 우선 반응형 웹(PWA)

## 1. 프로젝트 배경

MealBudgetDiet은 가족 또는 가까운 사람들과 공용 식비를 기록하고, 월 예산 대비 소비 현황과 기간별 통계를 확인하기 위한 서비스다.

실제 생활에서 지속적으로 사용하는 것을 첫 번째 목표로 하며, 요구사항 정의부터 설계, 구현, 테스트, 배포까지의 과정을 백엔드 개발 포트폴리오로 활용한다.

## 2. 프로젝트 목표

1. 공용 자금에서 사용한 식비 내역을 저장하고 조회한다.
2. 초대된 사용자들이 동일한 식비 내역을 조회하고 함께 편집한다.
3. 특정 기간의 지출 합계, 예산 사용률, 소비 추이와 카테고리별 통계를 제공한다.
4. 스마트폰에서 빠르게 입력할 수 있고 홈 화면에 설치 가능한 PWA를 제공한다.
5. 실제 데이터와 분리된 포트폴리오용 데모 환경을 제공한다.

## 3. 대상 사용자 및 사용 환경

- 하나의 실제 공용 장부를 2~5명이 함께 사용한다.
- 사용자는 가족 또는 가까운 사람을 전제로 한다.
- 스마트폰 사용 경험을 최우선으로 설계한다.
- PC에서도 모든 기능을 사용할 수 있는 반응형 화면을 제공한다.
- 서비스의 기준 통화는 대한민국 원(KRW)이다.
- 날짜와 월별 통계의 기준 시간대는 Asia/Seoul이다.

## 4. 사용자 유형과 권한

### 4.1 일반 참여자

모든 참여자는 다음 작업을 수행할 수 있다.

- 식비 등록, 조회, 수정, 삭제
- 대시보드 및 통계 조회
- CSV 내보내기
- 초대 코드 발급 및 취소
- 본인 회원 탈퇴

### 4.2 관리자

관리자는 일반 참여자의 모든 권한과 함께 다음 작업을 수행할 수 있다.

- 기본 월 예산 설정
- 특정 예산 주기의 예산 변경
- 월 예산 시작일 변경
- 카테고리 추가, 이름 변경, 삭제
- 다른 참여자의 관리자 지정 및 해제
- Push 알림 기준 사용률 변경

관리자는 여러 명 지정할 수 있다.

### 4.3 참여자 관리

- 다른 참여자를 강제로 탈퇴시키는 기능은 제공하지 않는다.
- 참여자는 본인이 직접 탈퇴한다.
- 탈퇴한 사용자의 이름은 삭제하지 않고 유지한다.
- 마지막 관리자가 탈퇴하면 실제 공용 장부가 종료된다.
- 장부 종료 전 비밀번호 재확인과 명시적인 최종 확인을 요구한다.
- 최종 확인이 완료되면 장부와 관련 데이터를 애플리케이션에서 즉시 영구 삭제한다.
- 인프라 백업에 남은 데이터는 별도의 백업 보존 정책에 따라 만료되며 사용자가 다시 접근할 수 없다.

## 5. 회원가입 및 인증

### 5.1 회원가입

- 이메일과 비밀번호로 가입한다.
- 최초 관리자 외에는 유효한 초대 코드가 있어야 가입할 수 있다.
- 누구나 자유롭게 가입하는 공개 회원가입은 제공하지 않는다.
- 가입 시 이메일 소유 인증은 수행하지 않는다.

### 5.2 초대 코드

- 모든 참여자가 초대 코드를 발급하고 취소할 수 있다.
- 하나의 초대 코드를 여러 사용자가 사용할 수 있다.
- 초대 코드는 만료일을 두지 않는다.
- 발급한 사용자가 취소하기 전까지 사용할 수 있다.

### 5.3 로그인

- 애플리케이션은 로그인 세션에 고정 만료일이나 미사용 만료 시간을 두지 않는다.
- 한 번 로그인한 기기는 사용자가 로그아웃하기 전까지 로그인 상태를 유지한다.
- 브라우저 데이터 삭제, 시크릿 모드 종료 또는 브라우저 자체 보존 정책으로 쿠키가 제거된 경우에는 다시 로그인해야 한다.
- 로그아웃하면 현재 로그인 상태를 즉시 종료한다.
- 비밀번호 변경·재설정 또는 회원 탈퇴 시 해당 사용자의 모든 기기 세션을 즉시 종료한다.

### 5.4 비밀번호 재설정

- 비밀번호를 잊은 사용자는 가입한 이메일로 일회용 재설정 링크를 받는다.
- 재설정 링크에는 별도의 만료 시간을 적용한다.
- 사용이 완료된 링크는 다시 사용할 수 없다.
- 비밀번호 재설정이 완료되면 해당 사용자의 모든 로그인 세션을 종료한다.

### 5.5 프로필 사진

- 사용자는 본인의 프로필 사진을 직접 등록, 교체, 삭제할 수 있다.
- 프로필 사진은 선택 항목이며 한 사용자당 한 장만 활성 상태로 유지한다.
- 프로필 사진이 없으면 표시 이름의 첫 글자를 기본 아바타로 표시한다.
- 같은 공용 장부의 활성 참여자는 서로의 프로필 사진을 볼 수 있다.
- JPEG, PNG, WebP 형식을 지원하고 업로드 원본은 파일당 최대 5MB로 제한한다.
- 서버는 실제 파일 형식과 이미지 디코딩 가능 여부를 검증하고 메타데이터를 제거한 뒤 표시용 WebP 이미지로 변환한다.
- 사용자가 프로필 사진을 교체·삭제하거나 탈퇴하면 더 이상 참조되지 않는 이미지 파일도 삭제한다.

## 6. 식비 관리

### 6.1 식비 데이터

| 항목 | 필수 여부 | 규칙 |
|---|---|---|
| 금액 | 필수 | 0보다 큰 원화 정수 |
| 사용 날짜 | 필수 | 연·월·일만 저장 |
| 카테고리 | 필수 | 활성 카테고리 중 하나 선택 |
| 상호명 | 선택 | 키워드 검색 대상 |
| 메모 | 선택 | 키워드 검색 대상 |
| 이미지 | 선택 | 최대 3장, 순서 유지 |
| 생성 일시 | 자동 | 시스템이 기록 |
| 최종 수정 일시 | 자동 | 시스템이 기록 |

- 모든 식비는 공용 자금에서 지출한 것으로 취급한다.
- 지출한 사용자 또는 결제한 사용자는 기록하지 않는다.
- 등록자와 수정자를 사용자 화면에 표시하지 않는다.
- 사용자별 지출 통계는 제공하지 않는다.

### 6.2 등록 및 수정

- 모든 참여자가 식비를 등록하고 수정할 수 있다.
- 첫 화면에서 팝업 입력창을 열어 빠르게 등록할 수 있다.
- 저장이 완료되면 대시보드의 예산 현황과 최근 식비를 갱신한다.
- 동일한 내역을 동시에 수정할 때 한 사용자의 변경이 조용히 덮어써지지 않도록 충돌을 감지하고 재확인을 요청한다.
- 식비 등록과 수정 화면에서 이미지를 추가하거나 제거하고 표시 순서를 변경할 수 있다.
- 한 식비에는 최대 3장의 이미지를 등록할 수 있다.
- JPEG, PNG, WebP 형식을 지원하고 업로드 원본은 파일당 최대 5MB로 제한한다.
- 서버는 확장자가 아닌 실제 파일 형식과 이미지 디코딩 가능 여부를 검증한다.
- 서버는 이미지 메타데이터를 제거하고 화면 표시 크기에 맞게 리사이징한 WebP 파일을 저장한다.
- 임시 업로드 후 식비 저장이 완료되지 않은 이미지는 정해진 보존 시간이 지나면 자동 삭제한다.

### 6.3 삭제

- 모든 참여자가 식비를 삭제할 수 있다.
- 삭제 확인 후 즉시 영구 삭제한다.
- 휴지통과 삭제 복구 기능은 제공하지 않는다.
- 사용자별 등록·수정·삭제 변경 이력은 저장하거나 화면에 제공하지 않는다.
- 생성 일시와 최종 수정 일시만 시스템 정보로 유지한다.
- 식비가 삭제되면 해당 식비에만 연결된 이미지도 함께 영구 삭제한다.

### 6.4 목록 및 검색

- 기본 정렬은 사용 날짜 최신순이다.
- 사용 날짜가 같으면 최근 등록된 내역을 먼저 표시한다.
- 처음 20개를 표시한다.
- 사용자가 ‘더 보기’를 누를 때마다 다음 20개를 추가로 불러온다.
- 다음 조건으로 검색하거나 필터링할 수 있다.
  - 시작일과 종료일
  - 카테고리
  - 상호명 또는 메모 키워드

## 7. 카테고리 관리

### 7.1 기본 카테고리

최초 장부에 다음 카테고리를 제공한다.

- 장보기
- 외식
- 배달
- 카페/간식
- 기타

### 7.2 카테고리 변경

- 관리자만 카테고리를 추가, 이름 변경, 삭제할 수 있다.
- 사용자가 필요한 카테고리를 추가할 수 있다.
- 이미 식비에서 사용된 카테고리도 삭제할 수 있다.
- 카테고리가 삭제되면 기존 식비의 카테고리는 빈값으로 변경한다.
- 통계에서는 카테고리가 없는 내역을 ‘분류 없음’으로 집계한다.

## 8. 예산 관리

- 관리자가 기본 월 예산을 설정한다.
- 별도 설정이 없는 월에는 기본 월 예산을 적용한다.
- 관리자는 특정 예산 주기의 예산만 별도로 변경할 수 있다.
- 남거나 초과한 예산은 다음 달로 이월하지 않는다.
- 각 월의 예산과 사용 금액은 독립적으로 계산한다.
- 예산 사용률이 80% 이상이면 대시보드에 주의 상태를 표시한다.
- 예산 사용률이 100% 이상이면 초과 상태를 표시한다.
- 예산 관련 이메일 알림은 제공하지 않는다.

### 8.1 월 예산 주기

- 월 예산 시작일은 공용 장부 단위로 관리하며 관리자만 변경할 수 있다.
- 기본 시작일은 1일이고 1~31 사이의 정수로 설정할 수 있다.
- 설정한 시작일이 존재하지 않는 달은 해당 월의 마지막 날을 시작일로 사용한다.
- 예산 주기는 설정한 시작일부터 다음 시작일 전날까지다.
- 예산 주기의 `yearMonth`는 주기가 시작된 날짜가 속한 연·월을 사용한다.
- 예를 들어 시작일이 25일이면 `2026-09` 예산 주기는 2026-09-25부터 2026-10-24까지다.
- 시작일 변경은 저장 완료 후 새로 조회하는 대시보드, 월 통계, 적용 예산과 Push 알림 판정에 즉시 적용한다.
- 시작일을 변경해도 식비 원본과 기존 월별 예산 금액은 변경하지 않고 새 주기 경계로 다시 집계한다.

### 8.2 월 예산 초과 위험 PWA 푸시 알림

새 식비가 등록된 직후 다음 값을 계산한다.

- 예산 사용률 = 현재 예산 주기의 누적 식비 ÷ 적용 예산 × 100
- 예상 주기 종료 지출 = 현재 예산 주기의 누적 식비 ÷ 오늘까지의 경과일수 × 예산 주기의 전체 일수

다음 두 조건을 모두 만족하면 PWA 푸시 알림 대상이 된다.

1. 예산 사용률이 장부의 Push 기준 사용률 이상이다.
2. 현재 소비 속도로 계산한 예상 주기 종료 지출이 적용 예산을 초과한다.

수식:

```text
budgetUsageRate >= pushUsageThreshold
AND
totalSpent / elapsedDays * daysInCycle > cycleBudget
```

알림 규칙:

- 식비 신규 등록 성공 직후에만 평가한다.
- 새 식비의 사용 날짜가 현재 예산 주기에 속할 때만 평가한다.
- 수정 또는 삭제는 알림 평가를 발생시키지 않는다.
- 경과일수는 현재 예산 주기 시작일부터 오늘까지이며 오늘을 포함한다.
- 조건을 처음 충족한 시점에 공용 장부와 예산 주기 기준 1회만 발송한다.
- 해당 예산 주기에 이미 발송했다면 이후 식비를 추가하거나 기준 사용률을 변경해도 다시 발송하지 않는다.
- 푸시 알림을 허용하고 활성 상태인 모든 참여자의 등록 기기로 발송한다.
- 푸시 권한을 허용하지 않은 사용자에게 이메일 등 다른 방식으로 대체 발송하지 않는다.

Push 기준 사용률 설정:

- 공용 장부 단위로 관리하며 관리자만 변경할 수 있다.
- 기본값은 80%다.
- 1~100 사이의 정수 백분율로 설정할 수 있다.
- 변경된 값은 이후 새 식비 등록으로 수행되는 알림 판정부터 적용한다.

## 9. 대시보드

로그인 후 첫 화면에 다음 내용을 표시한다.

- 현재 예산 주기의 예산
- 현재 예산 주기의 사용 금액
- 남은 예산 또는 초과 금액
- 예산 사용률
- 예산 상태
- 식비 빠른 등록 버튼
- 최근 식비 내역

예산 상태는 다음 기준으로 구분한다.

| 사용률 | 상태 |
|---:|---|
| 80% 미만 | 정상 |
| 80% 이상 100% 미만 | 주의 |
| 100% 이상 | 초과 |

## 10. 통계

### 10.1 조회 기간

다음 빠른 기간 선택을 제공한다.

- 현재 예산 주기
- 직전 예산 주기
- 최근 3개 예산 주기
- 올해

사용자는 시작일과 종료일을 직접 지정할 수도 있다.

### 10.2 제공 통계

- 선택 기간의 총 식비
- 선택 기간에 적용되는 예산 대비 사용률
- 일별 사용 금액 추이
- 카테고리별 사용 금액과 비중
- 이전 동일 길이 기간 또는 직전 예산 주기 대비 증감
- 카테고리가 삭제된 식비의 ‘분류 없음’ 집계

사용자별 지출 통계는 제공하지 않는다.

## 11. CSV 내보내기

- 사용자가 선택한 기간의 식비 내역을 CSV 파일로 내려받을 수 있다.
- CSV에는 금액, 사용 날짜, 카테고리, 상호명, 메모를 포함한다.
- 삭제된 카테고리는 ‘분류 없음’으로 출력한다.
- CSV 또는 다른 파일을 이용한 데이터 가져오기 기능은 제공하지 않는다.

## 12. PWA 및 오프라인

- 스마트폰 홈 화면에 설치할 수 있는 PWA로 제공한다.
- 스마트폰 화면을 우선 설계하고 PC 화면에 반응형으로 대응한다.
- 인터넷 연결이 없더라도 앱을 실행할 수 있다.
- 오프라인 상태에서는 연결 필요 안내 화면만 보여준다.
- 오프라인 조회, 등록, 수정, 삭제 및 자동 동기화는 제공하지 않는다.
- 사용자가 허용하면 서비스 워커를 통해 PWA 푸시 알림을 받을 수 있다.
- 사용자는 기기별로 푸시 알림을 활성화하거나 해제할 수 있다.
- Push 기준 사용률은 장부 관리자 설정이고, 기기별 수신 여부는 각 사용자의 설정이다.

## 13. 포트폴리오 데모

- 실제 개인 데이터와 분리된 데모 계정과 데모 장부를 제공한다.
- 데모 데이터는 실제 데이터 저장소와 논리적 또는 물리적으로 분리한다.
- 검토자는 데모 계정으로 식비 관리와 통계 기능을 체험할 수 있다.
- 데모 데이터는 정해진 주기에 따라 초기 상태로 자동 복원한다.
- 데모 환경을 통해 실제 사용자 데이터에 접근할 수 없어야 한다.

실제 서비스에서는 공용 장부 하나만 지원하며, 데모 장부는 다중 장부 기능이 아니라 별도 데모 환경으로 운영한다.

## 14. 비기능 요구사항

### 14.1 보안

- 비밀번호를 복호화할 수 없는 안전한 해시로 저장한다.
- 인증이 필요한 모든 API에서 로그인 상태를 확인한다.
- 관리자 기능은 서버에서 관리자 권한을 다시 검증한다.
- 초대 코드와 비밀번호 재설정 토큰을 원문 그대로 저장하지 않는다.
- 운영 비밀값과 개인정보를 Git 저장소에 커밋하지 않는다.
- 운영 환경은 HTTPS를 사용한다.
- 업로드 이미지는 파일 확장자와 무관하게 허용된 이미지 형식인지 서버에서 다시 검증한다.
- 이미지 저장소는 비공개로 운영하며 권한을 확인한 요청에만 이미지를 제공한다.
- 이미지에서 EXIF를 포함한 메타데이터를 제거한다.

### 14.2 데이터 정합성

- 모든 금액은 원화 정수로 저장하고 계산한다.
- 통계 합계는 식비 원본 데이터와 일치해야 한다.
- 동시 수정 충돌이 발생하면 클라이언트에 충돌 응답을 전달한다.
- 월 예산 계산에는 장부에 설정된 시작일과 Asia/Seoul 기준 날짜 경계를 사용한다.
- 식비 이미지 수는 최대 3장이고 이미지 정렬 순서가 중복되지 않도록 보장한다.

### 14.3 대상 규모

- 하나의 실제 공용 장부와 2~5명의 참여자를 기준으로 한다.
- 초기 버전에서 대규모 트래픽이나 다중 조직을 위한 구조는 목표로 하지 않는다.
- 측정된 문제가 없는 상태에서 캐시, 메시지 브로커 또는 별도 통계 배치를 추가하지 않는다.

## 15. MVP 범위

### 15.1 실제 사용을 위한 MVP

- 초대 코드 기반 이메일 회원가입과 로그인
- 로그아웃 전 로그인 유지 및 비밀번호 재설정 시 전체 세션 해제
- 공용 장부 참여자와 관리자 권한
- 식비 등록, 조회, 수정, 삭제와 이미지 최대 3장 첨부
- 사용자 프로필 사진 등록·교체·삭제
- 카테고리 관리
- 기본 월 예산과 특정 예산 주기 예산 변경
- 장부 공통 월 시작일과 Push 기준 사용률 설정
- 대시보드와 기간별 통계
- 목록 검색과 필터
- CSV 내보내기
- 모바일 우선 반응형 PWA
- 오프라인 안내 화면
- 조건부 월 예산 초과 위험 PWA 푸시 알림

### 15.2 포트폴리오 완성 단계

- 실제 환경과 분리된 데모 환경
- 데모 데이터 자동 초기화
- 자동화 테스트 및 CI
- API 문서
- 아키텍처 구성도와 ERD
- 운영 배포와 모니터링
- 기술 선택과 문제 해결 과정 문서화

## 16. 제외 범위

초기 버전에서는 다음 기능을 개발하지 않는다.

- 여러 개의 실제 식비 장부
- 네이티브 Android 또는 iOS 앱
- 소셜 로그인
- 가입 시 이메일 인증
- 여러 통화와 환율
- 지출 사용자 및 사용자별 소비 통계
- 결제수단과 식사 시간 구분
- 영수증 OCR과 이미지 내용 자동 분석
- CSV 가져오기
- 삭제 내역 복구
- 사용자별 변경 이력
- 다른 참여자의 강제 탈퇴
- 이메일 예산 알림
- 월 예산 초과 위험 이외의 PWA 푸시 알림
- 오프라인 데이터 조회와 동기화
- 실시간 공동 편집 화면
- 초기 단계의 Redis, Kafka, Airflow 또는 마이크로서비스

## 17. 핵심 인수 조건

1. 초대 코드가 없는 신규 사용자는 가입할 수 없다.
2. 초대받아 가입한 사용자는 다른 참여자와 동일한 식비 목록을 조회하고 편집할 수 있다.
3. 한 참여자가 등록하거나 수정한 식비는 다른 참여자의 조회 결과와 통계에 반영된다.
4. 일반 참여자는 예산, 카테고리, 관리자 권한을 변경할 수 없다.
5. 기간과 카테고리, 키워드로 식비를 조회할 수 있다.
6. 선택한 기간의 총액과 카테고리별 합계가 원본 식비 합계와 일치한다.
7. 월 예산 사용률이 80%와 100%에 도달하면 화면 상태가 변경된다.
8. 선택한 기간의 식비를 CSV로 내려받을 수 있다.
9. 스마트폰 홈 화면에 설치하고 주요 기능을 사용할 수 있다.
10. 오프라인에서는 데이터 변경을 허용하지 않고 연결 필요 안내를 표시한다.
11. 포트폴리오 데모에서 실제 사용자 데이터에 접근할 수 없다.
12. 마지막 관리자 탈퇴로 장부를 삭제할 때 비밀번호와 최종 확인을 모두 요구한다.
13. 현재 예산 주기의 식비 신규 등록 후 예산 사용률이 설정된 Push 기준 이상이고 현재 소비 속도의 예상 주기 종료 지출이 적용 예산을 초과하면, 해당 예산 주기에 처음 한 번만 푸시 알림을 발송한다.
14. 식비 한 건에 JPEG, PNG 또는 WebP 이미지를 최대 3장까지 등록·수정·조회할 수 있고 파일당 5MB를 초과하면 거절한다.
15. 관리자가 월 시작일을 변경하면 모든 참여자의 대시보드, 월 통계, 예산과 Push 판정에 같은 예산 주기가 적용된다.
16. 애플리케이션의 시간 제한으로 로그인 세션이 만료되지 않으며 비밀번호 변경·재설정·탈퇴 시에는 모든 세션이 종료된다.
17. 사용자가 5MB 이하의 프로필 사진을 등록·교체·삭제할 수 있고 같은 장부 참여자에게 표시된다.
18. 관리자가 Push 기준 사용률을 1~100%로 변경하면 이후 식비 등록부터 해당 기준으로 알림 조건을 평가한다.
